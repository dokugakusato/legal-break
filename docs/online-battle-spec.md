## 1. 目的

現在 HTML / CSS / JavaScript で制作している「LEGAL BREAK」を土台に、ダウンロード不要・URLアクセスだけで遊べるリアルタイムのオンライン対戦モードを追加する。

コンセプトは「法律知識そのものが戦闘力になるオンライン格闘ゲーム」。行政書士試験形式の5択問題を2人へ同時出題し、正解の速さと正確さで攻撃し、相手のHPを0にした側が勝利する。

## 2. 基本方針

- 既存の LEGAL BREAK の HTML / CSS / JavaScript を最大限流用する。
- アプリ化・ダウンロード式にはしない。PC・Mac・スマートフォンのブラウザで動作させる。**スマホ（iPhone・Android）がメイン**。
- 既存のストーリーゲームを壊さず、メニューに「ONLINE BATTLE」を別モードとして追加する。
- 対戦画面は**スクロールなしの1画面**に収める（問題文・5択・両者のHP・キャラクター）。5択は文が長いので、文字サイズと配置を最優先で設計すること。

## 3. バックエンド構成（決定事項）

- バックエンドは**既存の Firebase**（ログインで使用中のプロジェクト）を使う。Supabase など別サービスは使わない。
- Firebase は **Blaze プラン（従量課金）に移行**する（移行・カード登録はオーナーが行う）。
- リージョンは**東京（asia-northeast1）**。
- 構成：
  - **Cloud Functions**：正誤判定・回答順の確定・ダメージ計算・勝敗判定・レーティング計算をすべてサーバー側で行う。
  - **Firestore**：ルーム、試合の状態、問題、戦績を保存。
  - **Realtime Database**：接続状態（切断検知）のみに使う（onDisconnect）。
  - **App Check**：ロボット・不正アクセス対策。
- **正解データは端末に送らない**。問題文と選択肢だけを配信し、正解は Functions だけが読める場所に保管する（Firestore のセキュリティルールでクライアントから読めないようにする）。
- 回答時刻は**Firebase のサーバー時刻**で記録する。端末の時計は使わない。回答の早い・遅いはサーバーが受け付けた順で決める。

## 4. 費用の安全対策（STEP 1 の前に必ず実施）

Google Cloud の予算アラートは通知が来るだけで課金を止めないため、以下を最初に設定する。

1. 予算を **月3,000円** に設定。
2. 予算を超えたら**自動で課金を停止する仕組み**（予算通知 → Pub/Sub → Cloud Function で請求先アカウントを外す、Google 公式手順の方式）を入れる。再開はオーナーの手動操作のみ。
3. App Check を有効化。
4. Cloud Functions に同時実行数・最大インスタンス数の上限を設定。

課金が停止しても、ストーリーモード（静的ページ）は遊べ続けるようにする。オンライン対戦だけが「メンテナンス中」と表示される形でよい。

## 5. ログインと参加条件

- **ルーム対戦（友達対戦）**：ログイン不要。プレイヤー名を入力すれば遊べる（Firebase 匿名ログインを裏で使う）。「登録しなくても遊べる」という既存方針を守る。
- **ランダムマッチ・レート戦（STEP 4 以降）**：メールアドレス登録（既存ログイン）が必要。レーティングを守るため。
- 匿名で遊んでいた人があとで登録したら、戦績を引き継げるようにする（匿名アカウントのリンク）。

## 6. 対戦ルール

### 基本
- 両者 **HP 1000** から開始。
- 1問の制限時間は **30秒**。
- 1試合は**最大15問**。
- 同じ問題・同じ選択肢の並びを、両者へ同時に表示する（シャッフルする場合も両者同一）。
- **先に正解した側だけが攻撃**し、その問題は終了。もう一方はその問題に答えられない。

### ダメージ（正解時、相手へ）
回答までの秒数で決める。
| 回答時間 | ダメージ |
|---|---|
| 0〜10秒 | 150 |
| 10〜20秒 | 100 |
| 20〜30秒 | 70 |

### 不正解
- 不正解すると、**自分に50ダメージ**。その問題はもう答えられない。
- **お手つき**：問題表示から**5秒以内の不正解**は「お手つき！」とし、**自分に100ダメージ**。問題を読まずに押す人を不利にするため。速い**正解**は罰しない（むしろ高ダメージ）。

### カウンター
- 相手が不正解した瞬間、こちらに「COUNTER CHANCE!」を表示。
- その後こちらが正解したら「COUNTER!」となり、通常ダメージの**2倍**を与え、必殺技演出（STEP 2）を発動。

### 決着がつかない場面
- **2人とも不正解**：それぞれ自分にダメージを受け、次の問題へ。
- **2人とも時間切れ（無回答）**：両者に30ダメージ（「にらみ合い」）。粘り続けて終わらない試合を防ぐため。
- **15問終わってもHPが残っている**：HPが多い側の判定勝ち。同じ場合はサドンデス（先に正解した方が勝ち）。
- **同時にHPが0**：引き分け。

### 回線切断
- 切断を検知したら相手に「相手の接続を待っています」を表示し、**15秒**待つ。
- 15秒以内に戻れば再開。戻らなければ切断した側の負け（不戦敗）。
- 切断中は問題のタイマーを止める。

## 7. 格闘演出（STEP 2）

- 正解した瞬間、キャラクターが相手へパンチ・キック・突進などで攻撃。
- 攻撃を受けると、のけぞる・吹き飛ぶ等のリアクション。
- HPが減るにつれて顔や服が徐々に傷つく（**既存のストーリー版の「ダメージでボロボロになる」演出を流用**）。
- HPが少なくなるとフラフラする瀕死状態。
- HP0の最後の一撃は派手なフィニッシュ演出 →「K.O.」表示 → 敗者が倒れる。

## 8. カウンター必殺技（STEP 2）

- カットイン → 必殺技 → 大ダメージ、の流れ。
- 技名は法律用語：「取消訴訟！」「執行停止！」「国家賠償請求！」「詐害行為取消権！」など。
- 技名は大きく表示し、読み上げる（既存の VOICEVOX 方式。ナレーションの読み方ルール、例：「荒野」＝こうや、「金」＝カネ は既存どおり守る）。

## 9. キャラクター

- **STEP 1 では新キャラを作らない**。佐藤 vs 色違いの佐藤で動かす。
- STEP 2 以降で 6〜8 種類に増やす（パワー型、スピード型、女性格闘家、老練な達人、スーツ姿の法律家、ワイルド系など）。
- キャラ性能で回答の有利不利は作らない。違いは見た目・通常攻撃・必殺技・勝利ポーズ・敗北モーションのみ。

## 9-2. 方針変更（2026-10-30）：ランダムマッチを主役にする

- 友達を誘う手間が大きいので、**最初から「ランダムマッチ」を主役**にする。友達対戦（ルームコード）は後回し（STEP 5以降、要望があれば）。
- ランダムマッチはログイン不要（匿名ログイン・名前だけ）で遊べる。レーティングを付ける段階（STEP 3）で、ランク戦だけメール登録を必須にする。
- **人が少ない時期の対策**：
  - 「ONLINE BATTLE」を押すと最大**20秒**相手を探す。見つからなければ**CPU（修行相手）と対戦**する。CPUであることは必ず画面に表示し、人間のふりはさせない。
  - CPUは問題ごとに「答えるまでの秒数」と「正解するかどうか」をサーバーが決める（正答率と速さは中くらい。強さは後で3段階にできる作り）。
  - CPUと戦っている間も相手探しは続けない（シンプルにするため）。試合後に「もう一度探す」を出す。
  - 画面に「今オンラインで対戦中の人数」を出す（人がいる時間帯が分かるように）。
  - Xで「毎晩21時は対戦タイム」のように告知して、人が集まる時間を作れるようにする（ゲーム側の作業は不要。運用で行う）。
- 以下の10章（友達対戦）の内容は、後回しの段階で使う。招待リンク・スタンプ・アプリ内ブラウザ対策の考え方はランダムマッチにもそのまま使う（スタンプは対戦相手との間で使う）。

## 9-3. 追加決定（2026-10-30）：ランクと保存を最初から入れる

- 画面の流れ：「ONLINE BATTLE」→「対戦相手を待っています…」→ 相手が来たら「**見つかった！**」→ VS画面（両者の名前・ランク・勝敗数）→ 3・2・1・FIGHT!
- **ランク（D・C・B・A・S）とランキングは STEP 1 から入れる**。
- 内部はレーティング（初期1500、Elo方式、計算はサーバーだけ）。表示ランクの目安：D＝1399以下／C＝1400〜1549（最初はC）／B＝1550〜1699／A＝1700〜1849／S＝1850以上。Sが多すぎる・少なすぎる場合は後で調整。
- **保存**：レーティング・勝敗数・名前はサーバーが `battlePlayers/{uid}` に保存（本人もスマホから書き換えできない）。
  - 登録しなくても、そのスマホ（ブラウザ）では記録が残る（匿名ログイン）。
  - メール登録すると、同じ記録のまま機種変更しても続きから遊べる（既存の「匿名→登録」のつなぎ方で、記録はそのまま引き継がれる）。
  - ランク戦にメール登録を必須にする案は取りやめ。
- **CPU戦はランクが変わらない**（練習扱い）。勝敗数にも数えない。
- **全国ランキング**：レーティング上位50人を表示（名前・ランク・勝敗数）。自分の順位も表示。
- タイトル画面と対戦メニューに、自分のランク・レーティング・勝敗数を表示。

## 10. 友達対戦（ルームコード）

- 「ROOM CREATE」で**6桁の数字コード**を発行。
- 友達が「ROOM JOIN」でコードを入力すると入室。
- 2人そろったら VS 画面 →「3 → 2 → 1 → FIGHT!」で開始。
- ルームは作成から**10分**誰も入らなければ自動で削除。
- **利用者が少ない最初の時期でも遊べるので、最初に完成させる。**
- 部屋を作ったら「LINEで誘う」「Xで募集」ボタンを出す。押すとコード入りのURL（例：`?room=482913`）が送れ、相手はタップするだけで入室できる（コードの手入力は不要）。
- **XやLINEのアプリ内ブラウザ対策**：
  - 対戦はGoogleログインを使わない（匿名ログインのみ）ので、アプリ内ブラウザでも遊べる作りにする。音は最初のタップで鳴らし始める。
  - LINEで送る招待リンクには `openExternalBrowser=1` を付け、LINEから開くと普通のブラウザ（Safari・Chrome）で開くようにする。
  - Xなどのアプリ内ブラウザで開かれたら、画面上部に「ブラウザで開く」案内を出す。Androidはボタン1つでChromeに切り替え、iPhoneは切り替えを試し、だめなら「右下（または右上）のメニュー →ブラウザで開く」を絵で案内する。案内は閉じてそのまま遊ぶこともできる。
  - 部屋で相手を待っている間は、LINEなどに切り替えても切断負けにしない（切断のルールは試合中だけ）。
- 自由に文字を打てるチャットは付けない（悪口・個人情報のやり取り・対戦中の答えの教え合いを防ぐため）。代わりに**決まった言葉のスタンプ**を使う：「よろしく！」「ナイス！」「参った！」「もう1戦！」「ありがとう！」など。スタンプは問題に答えている間は送れず、VS画面・解説画面・試合後だけ送れる。連打は数秒に1回まで。

## 11. ランダムマッチング（STEP 4）

- 「ONLINE BATTLE」→「対戦相手を検索中……」
- 待機中のプレイヤーから、レーティングの近い相手を優先して組む。待ち時間が長くなるほど、組める実力差の幅を広げる。
- **60秒**見つからなければ「今は相手がいません。友達対戦やCPU戦はいかが？」と案内。
- 成立後は VS 画面（プレイヤー名・ランク・勝敗数）→ カウントダウン → FIGHT!

## 12. ランク・レーティング（STEP 5）

- 表示ランク：D → C → B → A → S。内部ではレーティングポイント（初期値1500）を持つ。
- **Elo レーティング**で計算（格上に勝つと大きく上がり、格下に負けると大きく下がる）。計算はすべてサーバー側。
- S ランクは上位のごく一部だけにし、希少価値を高くする。
- 上位者には「全国1位」「行政法の鬼」「記述の覇者」などの称号や特殊オーラを検討。

## 13. 特別演出・ランキング（STEP 6）

- S ランク同士では「S RANK BATTLE」の専用演出。
- ランキング上位者同士では専用BGM・エフェクト・VS画面。
- 全国ランキング画面。
- 曲は既存方針どおりマンネリ防止のため、対戦曲・ボス曲を定期的に入れ替えられる作りにする。

## 14. 問題データ

- **まずは自作のオリジナル5択**（10問程度）で動作確認する。過去問の収録は、出題元の利用条件を確認してから。
- 問題の元ネタは、オーナーの独学応援チャンネルの論点ノート（民法・行政法）を使う。
- 行政書士試験で頻出のど真ん中の論点を優先する。
- 各問題に「**型**」タグを付ける：
  - **消去法型**：難しい選択肢があっても、他の4つが明らかに違うので決まる
  - **冒頭判断型**：問題文の前半で答えが決まり、後半は読まなくてよい
  - **キーワード型**：選択肢の一語（「できる」「しなければならない」等）で正誤が決まる
- 問題データの形式（例）：
  - 問題ID、分野（民法／行政法）、論点名、型、問題文、選択肢5つ、正解番号（サーバー専用）、解説
- 問題文・正解・解説の法律的な正しさは、オーナーが確認してから本番に入れる。

## 15. 1問終了後の解説画面

- 正解、解説、問題の「型」を表示（例：「この問題は冒頭2行で決まる型です」）。
- 数秒で次の問題へ自動で進む（タップで早送り可）。
- **マーカー機能（STEP 2 以降）**：回答中、問題文に線を引ける。**対戦中は相手に見せない**（カンニング防止・画面が散らからないように）。1問終了後の解説画面で、自分と相手が線を引いた箇所を並べて表示する。

## 16. 開発順序

### STEP 0：費用の安全対策
4章の予算・自動停止・App Check・上限設定。

### STEP 1：ランダムマッチで2人対戦 → K.O.まで（ランク・保存・ランキング込み）
- ランク（D〜S）・レーティング・勝敗数の保存、全国ランキング（9-3章）
- 「ONLINE BATTLE」→ 相手探し（最大20秒）→ 見つからなければCPU戦
- 同じ問題を同時表示（正解は端末に送らない）

## 記述バトルのルール（2026-10-31 決定）
- 紙芝居（4コマ）で事件を見たあと FIGHT。答案に入る正解キーワードの札を選んで「攻撃発動」。順番は自由。
- キーワードごとに点数（合計20点）。ダメージ＝点×40×倍率。
  - 1枚＝単発攻撃（×1）
  - 2枚同時＝中技（×1.5）
  - 3枚同時＝大技（×2、キャラの必殺技カットイン）
  - 4枚以上同時＝超ウルトラ技**天変地異**（一撃K.O.）。キーワードが3つの論点は、最初の一撃で全部出せば天変地異
- 1枚でも答案に入らない札が混じっていたら、点はもらえず自爆ダメージ（出した枚数×60）、2秒動けない。自爆でHP0なら負け。
- 20点そろったら、その一撃がとどめ（K.O.）。
- 時間切れなし。どちらかが倒れるまで続く（放置対策として20分だけ安全装置：点の高い方の勝ち）。
- 経験値（レート）：勝ち方で倍率。天変地異×2、大技でとどめ×1.5、中技でとどめ×1.2、単発×1。元の値は相手のランク（レート）が高いほど大きい。負けた側は普通どおり。CPU戦はランクが変わらない。
